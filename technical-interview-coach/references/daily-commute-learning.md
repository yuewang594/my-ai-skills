# Daily Commute Learning

## Goal

Create a lesson that can be read and mentally worked through in 15-20 minutes during a commute.

The lesson must be compact, practical, interview-oriented, and cumulative.

Do not overload the reader.
Prefer one main concept plus one closely related concept over broad coverage.

## Stats Lesson Format

Every Stats daily lesson must include:

### 1. Concept
Name and define the concept in precise but accessible language.

### 2. Why it matters
Explain why a Product Data Scientist should care and where it appears in interviews or real work.

### 3. Example
Use a concrete product or experiment example.

### 4. Explain it to a 5-year-old
Use a very simple analogy without distorting the underlying idea.

### 5. Interview intuition
Explain what interviewers are actually testing and what common traps exist.

### 6. One worked mini-example
Walk through a small numerical or logical example.

### 7. Test question
Give one question that tests understanding.
Do not immediately reveal the answer.

### 8. Optional stretch question
Add one Staff-level twist if the concept supports it.

## Python Lesson Format

Every Python daily lesson must include:

### 1. Code snippet
Use a short, realistic snippet in Python, NumPy, or Pandas.

### 2. What the syntax means
Explain key syntax constructs used in the snippet.

### 3. What each function does
Describe each important method/function in plain language.

### 4. Line-by-line logic
Explain what each line is doing and how the data changes.

### 5. Why it is written this way
Explain the intent behind the implementation choice.

### 6. What it is trying to achieve
Tie the code back to a business or analytical objective.

### 7. Pitfalls
Cover likely issues such as:
- nulls
- duplicates
- sorting
- index alignment
- groupby semantics
- merge cardinality
- type coercion
- edge cases
- performance
- silent failures

### 8. Code-review question
Ask whether the candidate would approve the code and what they would change.

### 9. Better version
When appropriate, provide a safer or more explicit implementation after the question section.

## Length

Target:
- 1,200-2,000 words total maximum
- 15-20 minutes to read and think through

Prefer concise diagrams using text only when needed.
Avoid long textbook derivations.

## Curriculum Behavior

Lessons should be cumulative and spaced.

If no weakness history exists, use the progression in `stats-topics.md` and `python-topics.md`.

If weakness history exists:
- 50% reinforce weaknesses
- 30% advance the planned curriculum
- 20% revisit older material for spaced repetition

## Tone

Use clear, serious, interview-prep language.
Do not over-simplify.
Do not rely on motivational filler.
