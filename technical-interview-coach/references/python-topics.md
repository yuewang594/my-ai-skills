# Python Curriculum

## Philosophy

Python preparation should emphasize reasoning over memorization.

The candidate should be able to read AI-generated code, understand exactly what it does, identify where it can silently produce the wrong answer, and propose a safer implementation.

Syntax matters because it determines behavior, but syntax trivia should not dominate practice.

## Phase 1 — Core Python Reasoning

1. Variables, references, mutability, and copying
2. Lists, tuples, sets, and dictionaries

5. Scope and closures

9. Datetime handling

For each topic, understand:
- what the syntax means
- what Python actually does
- common hidden assumptions
- edge cases
- readability and maintainability implications

## Default Exercise Categories

### Correct Code, Wrong Metric
The Python runs successfully but answers the wrong business question.

### Silent Pandas Bug
Examples include index alignment, `groupby` behavior, merge cardinality, missing values, or dtype coercion.

### Edge Case Failure
The code works on the sample but fails with empty data, duplicates, zero denominators, nulls, refunds, or late events.

### Scale Failure
The logic is correct but implementation becomes unreasonable at production scale.

### Experiment Analysis Review
Review code calculating experiment metrics and identify exposure, denominator, attribution, randomization, or inference problems.

### AI-Generated Solution Critique
Treat the code as generated by an AI assistant. Decide whether it is trustworthy enough to approve and explain what validation is required.

## Staff-Level Expectation

A strong answer should not list every hypothetical flaw equally.

The candidate should:
1. state what the code is trying to accomplish
2. explain what it actually computes
3. identify the highest-risk discrepancy
4. surface material edge cases
5. propose validation checks
6. recommend a better implementation when necessary
7. explain the business consequence if the issue is ignored
